# 康复智伴测试文档

## 1. 测试目标

本轮测试重点验证以下内容：

- 当前主链功能与既有版本保持一致
- Java 主后端能承接前端主业务接口
- 姿态识别微服务链能够独立运行
- 本地药品识别副链独立可用且不影响正式主链
- 前端页面在登录、总览、上传、用药、康复、AI 助手链路中可正常交互

## 7. 运行时数据流量与性能分析

### 7.1 总览页

核心请求：

- `GET /api/home/summary`
- `GET /api/devices`
- `GET /api/analyze/reports`
- `GET /api/rehab/plan`

特点：

- 读请求为主
- 并发加载多个摘要接口
- 主要耗时不在首页，而在模型相关接口

### 7.2 上传分析

链路：

1. `POST /api/analyze/tasks`
2. `GET /api/analyze/tasks/{id}`
3. `POST /api/analyze/tasks/{id}/save`
4. `POST /api/rehab/plan/apply`

特点：

- 模型分析和计划草案生成耗时最长
- 前端已为“保留并生成康复计划”放宽等待时间

### 7.3 药品识别

正式主链：

- `POST /api/medications/recognize`

副链：

- `POST /api/medications/recognize/custom-model`
- `POST local_medication_api /recognize/medications`

特点：

- 正式主链受外部模型网关影响
- 本地副链主要消耗在检测与 OCR
- 两条链并行，但默认互不替换

### 7.4 姿态识别

链路：

1. 前端提交视频
2. `posture-backend` 创建任务并入 Redis
3. `posture-inference-service` 消费任务并推理
4. 结果回写数据库
5. 前端轮询展示结果

特点：

- 这是最需要并发治理的链路
- Redis 用于削峰和保证多任务不丢失

## 8. 风险与边界

- 外部大模型网关可能超时
- Web 提醒不是原生后台闹钟
- Health Connect 仍需要原生桥接
- 本地药品副链当前仍是“可运行副链”，不是默认主链
