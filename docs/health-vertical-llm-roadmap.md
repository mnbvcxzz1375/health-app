## 一、定位与核心理念

我们不是在做一个通用聊天模型，而是在构建一个**健康多模态、多上下文、多任务专属模型系统**。

核心理念：
- **数据驱动**：所有健康建议基于用户真实监测数据，而非模型猜测
- **上下文感知**：模型接收完整的个人健康画像，包括慢病、用药、睡眠、压力等
- **安全优先**：高风险问题必须触发"建议线下就医"兜底
- **可解释输出**：每个建议都关联具体数据指标和阈值

## 二、三层架构

### 第一层：短期可落地（已实现）

以现有 `kimi-k2.5` 模型为底座，通过结构化 Prompt 工程实现健康专属智能体：

**已实现能力：**
- 健康评分引擎 v2：10 维度评分（心率、睡眠、压力、VO2Max、锻炼、站立、恢复、活动、血压、用药依从性）
- 个人基线对比：`population_score * 0.4 + personal_baseline * 0.35 + trend_score * 0.25`
- 上下文注入：AI 接收用户画像、每日监测、活跃关注、当前用药、历史记忆
- 药物识别与解释：OCR + 大模型 → 结构化药学信息 + 老人可读版本
- 记忆写回：每次 AI 对话后提炼 1 条记忆存入 `user_context_memory`

**Prompt 工程策略：**
```
系统角色：中文健康管理助手
输入：用户画像 + 今日监测 + 活跃关注 + 当前用药 + 历史记忆 + 用户问题
输出约束：JSON 格式 {answer, suggestions[3], disclaimer}
安全约束：每次回答必须包含免责声明
```

### 第二层：中期增强（比赛展示重点）

#### 2.1 健康领域数据集建设

| 数据类型 | 来源 | 用途 |

#### 2.2 监督微调数据格式

```json

  "instruction": "用户问：我最近睡眠质量下降，怎么办？",
  "input": "用户画像：28岁男性，身高172cm，体重65kg\n今日监测：睡眠评分65，压力指数72\n当前用药：降压药",
```

| 维度 | 指标 | 目标 |

| 风险保守性 | 高风险问题安全提示率 | 100% |

### 第三层：长期答辩亮点

#### 3.1 RAG + 医疗知识库

- 向量数据库存储药品说明书、慢病指南、健康科普材料
- 用户提问时先检索相关知识片段，再由模型生成回答
- 确保回答有据可查，减少幻觉

#### 3.2 用户上下文记忆系统

- **短期记忆**：当日监测数据、当前活跃关注
- **中期记忆**：近 7 天趋势、用药依从性记录
- **长期记忆**：慢病标签、基线数据、历史 AI 交互摘要

#### 3.3 专病子模型

| 子模型 | 输入 | 输出 |
|--------|------|------|
| 高血压管理 | 血压趋势、用药记录、饮食习惯 | 用药提醒、饮食建议、就医时机 |
| 睡眠管理 | 睡眠评分、入睡时间、压力指数 | 作息调整、放松训练、环境建议 |
| 老年安全用药 | 药物清单、剂量、时间 | 联用禁忌、依从性提醒、副作用监测 |

## 三、答辩表述要点

### 数据来源清晰
- 健康监测数据来自 Apple HealthKit + 智能穿戴设备
- 药物信息来自 OCR 识别 + 国家药品数据库
- 用户上下文来自系统自动聚合，非人工标注

### 模型能力边界清晰
- 不做诊断，只做健康管理和建议
- 不替代医生，每次回答附免责声明
- 高风险问题自动触发就医建议

### 输出可解释
- 每个评分都有基线对比和偏移量
- 每个建议都关联具体数据指标
- 用户可以查看"为什么是这个分数"

### 有安全兜底
- 心率 > 120、血压 > 180/110、睡眠评分 < 50 → 自动触发就医建议
- 药物识别置信度 < 70% → 提示用户人工确认
- AI 回答中包含"不确定"关键词 → 自动追加安全提示

### 能服务老人真实场景
- 大字号、高对比 UI
- 语音播报药物说明
- 语音确认服药状态
- 照护者异常通知

## 四、技术实现路径

```
用户数据采集层
  ├── Apple HealthKit (心率、睡眠、步数、HRV)
  ├── 智能穿戴设备 (蓝牙 BLE)
  └── 用户手动输入 (药物、症状)
        │
数据聚合层 (ContextService)
  ├── identity_context (年龄、性别、身高体重)
  ├── health_context (慢病标签、风险等级)
  ├── medication_context (当前药物、依从性)
  ├── behavior_context (睡眠习惯、活动水平)
  ├── interaction_context (AI 问答历史)
  └── care_context (照护者通知)
        │
评分引擎层 (HealthScoringService)
  ├── 10 维度评分
  ├── 个人基线对比
  ├── 趋势分析
  └── 风险标签 (attention_type)
        │
AI 推理层 (DashScopeService + ConsultService)
  ├── 上下文注入 Prompt
  ├── 结构化 JSON 输出
  ├── 安全兜底检查
  └── 记忆写回
        │
展示层 (Vue 3 + Vuetify)
  ├── 健康评分仪表盘
  ├── AI 助手对话
  ├── 药物扫描识别
  └── 老人友好 UI
```

## 五、比赛先进性总结

| 维度 | 我们的方案 | 通用方案 |
|------|-----------|---------|
| 数据接入 | Apple HealthKit + 多设备 | 单一数据源 |
| 评分算法 | 10 维度 + 个人基线 + 趋势 | 静态规则 |
| AI 上下文 | 6 域健康画像 + 记忆系统 | 无上下文 |
| 药物管理 | OCR + LLM + 老人版 + 语音 | 简单闹钟 |
| 安全机制 | 多层兜底 + 置信度检查 | 无安全机制 |
| 适老化 | 大字号 + 语音 + 单步操作 | 无适老设计 |
